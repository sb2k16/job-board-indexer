# Website: browsing the index (2026-11-13)

Goal: a product website over the job index where anyone can browse jobs, boards and companies
with filters. Code: `web/`.

## Shape

- **Next.js 15 (App Router), server-rendered.** Every page queries OpenSearch on the server, so
  the browser never talks to OpenSearch and the search cluster can stay VPC-only on AWS.
- **The URL is the state.** Every filter is a query parameter (`/jobs?q=engineer&remote=true&company=Ramp`),
  so results are shareable, bookmarkable and work without JavaScript; client components only push
  new URLs.
- **Reads only the `jobs` alias** and, optionally, the crawler's `board_state` table
  (`DATABASE_URL`) for crawl health on `/boards`. Without a database the page shows job counts only.

## Pages

| Path | Shows |
| --- | --- |
| `/` | Totals (open jobs, employers, boards, last re-check), platforms, top employers, recently indexed |
| `/jobs` | Search with keyword, location and facets; 20 per page, up to 50 pages |
| `/jobs/{job_key}` | Description, apply link, where the job was found, dates, more from the employer |
| `/companies` | Every employer with open jobs, by count or A–Z |
| `/boards` | Every board: platform, ATS or job board, open jobs, last crawl, outcome, snapshots |

## Filters

Keyword (title, company, location, description; `simple_query_string`, so stray quotes or brackets
never fail), location (text match), date posted (24 h, 7 d, 30 d: `posted_at`, or `first_seen` when
the platform has no post date), remote, employment type, company, source platform (grouped as ATS
or job board), board, country, status (open, closed, all). Sort: best match, newest posted,
recently indexed.

Country, company, platform, board, type and remote are multi-select facets: their filters go into
`post_filter`, and each facet's aggregation applies every other facet's filter but not its own, so
picking Ramp still shows the counts for other companies.

## Decisions

- **Country is a field, not a text match.** Filtering `location=US` literally matched 288 of 3,980
  jobs, missing "United States", "New York, NY", "Remote (US)" and the rest. The crawler now writes
  `countries` (ISO 3166-1 alpha-2, a list: "SF, NYC or Remote in Canada" is US and CA), resolved by
  `location/CountryResolver.java` from the platform's structured country plus the free-text location:
  country names in seven languages, US states and Canadian provinces (names, and codes after a comma),
  codes in brackets ("Hamburg (DE)"), uppercase-only US/UK/USA/UAE and city abbreviations, and a list
  of major cities; longest phrase first, so "New Mexico" is never Mexico. An unrecognised location
  gets no country rather than a guess. The site shows a Country facet, and a location box holding
  just a country ("US", "Deutschland") becomes that country filter.
- **Employment type is grouped in the UI** (Full-time, Part-time, Internship, Contract / temporary,
  Other), because platforms spell it 20+ ways (`FullTime`, `fulltime_permanent`, `PRN/On-Call`...).
  A bucket filters on every raw value in it. Normalising at ingest is the better long-term fix.
- **Highlights are never rendered as HTML.** OpenSearch wraps matches in private-use characters
  (U+E000, U+E001), which the page splits into `<mark>` elements. Control characters were tried first
  and broke: OpenSearch trims fragments with Java's `String.trim()`, which strips everything up to
  U+0020, so a match at the start of a title lost its opening marker.
- **Links from the index** become hrefs only when they are http(s), and open with
  `rel="noopener noreferrer nofollow"`.
- **Paging stops at 1,000 results.** Narrowing with a filter is the answer past that.

## Running

```sh
cd web && npm ci && cp .env.example .env.local
npm test && npm run build && npm start          # http://localhost:3000
```

Or as part of the local stack: the `web` service in `local/docker-compose.yml` (image built from
`web/Dockerfile`).
