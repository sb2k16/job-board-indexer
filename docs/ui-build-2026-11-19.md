# Website build from the v0.2 mocks (2026-11-19)

The Next.js app in `web/` now follows the v0.2 mocks (docs/ui-redesign-2026-11-18-review.md):
Home, Jobs (search), Job page, Companies, How it works, and an internal `/admin` crawl health page
behind a password. Deployed to the load balancer's AWS address (no domain yet).

## What was built

- **Design**: the mocks' tokens and components in `app/globals.css`; Source Serif 4, IBM Plex Sans
  and IBM Plex Mono self-hosted by next/font. Rows, not cards. The one accent marks "New" and
  "Still listed". Responsive to 390 px: stacked search, horizontally scrolling filter chips, a
  "Filters · N" toggle for the rail.
- **Public pages name no platform** and use no crawl wording. `lib/source.ts` says where a job is
  listed: "Still listed on Stripe’s careers site" for an employer's ATS, the board's address for a
  job board; the button reads "Apply on Stripe’s site".
- **Filters**: Remote (Any / Remote only), Date posted, Job type, Company, Location (country).
  Source platform, board and status filters left the public rail; links that carry them still work
  and show as chips. Sort: Most relevant (with keywords) / Most recent.
- **`/boards` redirects to `/admin`.** The public page with crawl outcomes is gone.

## Left out, because the data does not exist yet

- Salary, company industry ("Healthcare · Retail"): not in the index.
- Admin "last 10 outcomes" bars: board_state keeps the last outcome and the failure streak, not a
  history. Admin "documents rejected by the index": in CloudWatch logs, not in the database.
- Refresh-group cadence and next run on admin: `group_refresh` has the last refresh only; the
  cadence is in config/groups.toml, which the web image does not carry. Cards show the last refresh.

## The admin login

- One password, `ADMIN_PASSWORD`; on AWS a generated 32-character secret `jbi/admin-password`
  (Secrets Manager) injected into the web container. Unset or under 12 characters: `/admin` is off.
- Session: cookie `jbi_admin` = `<expiry>.<HMAC-SHA256>`, key derived from the password (changing it
  ends every session); 12 hours; HttpOnly, SameSite=Strict, path `/admin`, Secure when the request
  came over HTTPS. Checked by `requireAdmin()` in each admin page on the server (no middleware).
- Sign-in is a server action (Next.js checks the Origin header against the host, which blocks
  cross-site posts). 10 failed attempts per client address per 15 minutes, 1 s delay per failure,
  in the task's memory.
- Found in testing: behind a proxy, Next.js 15 (standalone, bound to 0.0.0.0) resolves a redirect
  from a server action or route handler against `http://0.0.0.0:3000`, not the visitor's host,
  so sign-in sent the browser to 0.0.0.0 whenever the host was not localhost. The actions return
  instead, and the client moves the browser with a relative URL. Page-level `redirect()` is not
  affected (its Location stays relative).
- **The load balancer is plain HTTP.** The password and the session cookie cross the internet
  unencrypted until there is a domain with a certificate (ACM) and an HTTPS listener.
